# Системный дизайн как память агента

12 слайдов для Hacker Sprint #2, рассчитанных на чтение без спикера.

- [PDF](deck.pdf)
- [Самодостаточная HTML-версия](deck.html)
- [Исходник Marp](deck.md)

История: гипотеза на примере задачи, скилл и цикл памяти, три эксперимента,
перенос уроков, сложность реляционной модели и краткое заключение.
Слайд 12 подводит итоги эксперимента.

## Пересборка

Нужны Python 3, Node.js/npm и Chrome/Chromium. Первый запуск скачивает Marp CLI 4.5.0.

```bash
python3 presentation/build.py
```

Скрипт обновляет PDF и HTML и встраивает изображения в HTML. Для PDF Marp получает
доступ к локальным изображениям. Слайд 3 показывает демо services-platform,
а не данные Mealie из эксперимента.

## Основания выводов

Ссылки под слайдами закреплены на коммитах источников, поскольку отчёты из PR #9
и PR #10 пока находятся в отдельных ветках.

| Слайды | Источник |
| --- | --- |
| 2–5 | `dataset/tasks.yaml`, `dataset/facts/snapshot-c0.md`, скилл и протокол раннера |
| 6 | Первый snapshot-прогон и разбор из [PR #10](https://github.com/podlodka-ai-club/kata/pull/10) |
| 7 | `2026-09-02-sonnet5-xmemory-full-r2.md` из [PR #9](https://github.com/podlodka-ai-club/kata/pull/9) |
| 8–9 | `2026-09-02-sonnet5-xmemory-precision-v1-canary.md` и attribution-отчёт из PR #9 |
| 10–11 | `skills/tech-facts/memory-protocol.md` и журналы проблем прогонов |
| 12 | Итоги экспериментов и протокола памяти, раскрытых на слайдах 4, 7–11 |

Вывод о сложности реляционной памяти относится к этому прототипу. Эксперимент
сравнивал режимы работы агента, а не реляционное хранилище с Markdown или другими
типами памяти. На слайде 7 показаны все запуски, включая исключённые по правилам
отбора. На слайде 8 показаны только две сопоставимые задачи. Наблюдаемую регрессию
нельзя причинно приписать памяти.
